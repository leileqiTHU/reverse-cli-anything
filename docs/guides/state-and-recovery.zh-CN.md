# 状态、异步执行与恢复
[English](state-and-recovery.md) · [工程手册](../HARNESS.zh-CN.md) · [运行回执](../runtime.zh-CN.md)

## 绑定真实上下文

按实际需要记录构建/模块、进程生命周期、桥接/会话代次、文档 ID、子上下文和对象选择，提交前再次检查。标题或文件名可能对应错误文档；指针只在所属生命周期内有意义。

区分应用状态、桥接状态和框架回执。历史成功回执证明当时记录了什么，不证明当前原生状态未变。读取自动保存文件的查询应注明来源，并结合原生身份和保存完成信号同步。

## 多步写入

首次修改前校验全部输入，记录计划步骤、旧状态和输入摘要。每步完成后保存创建对象 ID 和后置条件。十个对象在第六个失败时，不能报告原子失败，也不能全部重做。

语义明确时优先原生事务。补偿是另一项操作：删除新对象、恢复旧值仍可能失败，也可能无法恢复历史、选区或外部效果；应记录实际观察，不能假定回滚成功。

请求 ID 标识提交尝试，同 ID 改参数必须拒绝。返回逻辑重复请求的旧结果前，判断是否需要核验对象当前状态。不同 ID 也可能表示有害的重复操作，因此基础去重不等于业务幂等。

## 状态判断

| 观察 | 分类及下一步 |
| --- | --- |
| 参数检查或已知提交前拒绝 | not-submitted，说明输入/状态问题 |
| 对应请求的终态及后置条件正确 | completed，另存原生证据 |
| 已知部分步骤改变状态 | partially-applied，保留 ID 与待完成步骤 |
| 超时、响应丢失、原生错误语义不明 | unknown，冲突写入前先观察 |
| 迟到的匹配终态结果 | 对账原请求，不为了取得响应而重发 |

未知原生任务可能仍运行时，不解除写入锁。共享网关只串行其自身写入，不能保护任意客户端或其他状态目录；说明锁的范围。控制器/worker 退出不证明目标中的排队工作已经停止。

进程崩溃时，本地保留日志和必要转储，定位最后一次确认的修改，检查已保存状态后再重开或恢复。存在备份不证明活动文档已恢复。

## 临时设置与预览

预览可能临时修改范围、分辨率、选区、相机、导出路径或活动上下文。保存具体字段和身份；只有同一操作仍拥有这些设置、原生任务不再需要它们时才恢复，避免覆盖中途用户修改。

分别记录获取预览和恢复是否成功。预览正确而恢复失败仍属部分完成；清理后再次查询，防止后续事件在主体操作结束后改动状态。

## 恢复交接

保留简洁记录：操作 ID、目标身份、最后确认步骤、创建/修改对象、worker/原生存活状态、证据位置、允许的只读观察及继续执行的条件。尽量通过状态查询暴露，避免新 Agent 从长篇终端记录中猜测。
