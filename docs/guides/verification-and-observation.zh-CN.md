# 验证与状态观察
[English](verification-and-observation.md) · [工程手册](../HARNESS.zh-CN.md) · [验收](../../acceptance/README.zh-CN.md)

## 设计能区分真假的检查

执行前定义每项请求预期的数据、计算结果或状态变化，以及适用的不应变化状态。存在稳定身份时用其核对，而不只看数量。返回零、文件非空、截图相符，单独都不足以证明许多任务正确。

按需选择请求、状态、持久化、产物及恢复层次。只读查询无须捏造保存/导出测试。同会话重开、新进程、新机器是不同范围；应用正常授权和平台限制需明确保留。

每项结果绑定目标构建、输入、配置及执行时间，同时保留拒绝、部分完成和未知结果的证据。

## 先诊断样本，再真实输入

构造已知数值、可区分输入或对象和明确预期结果的小样本，每次改变一个相关条件。根据契约覆盖边界值、空输入、无效引用及编码差异。

根据原生单位、数值精度与序列化规则确定容差，记录调用方与原生表示之间的转换，包括舍入、坐标系或参考系；拒绝超过该范围的差异。

再检查具有真实规模、结构、元数据和依赖的代表性输入。保留原始输入并记录预处理，区分转换成功与原生直接处理原格式成功。

同时检查操作的结构结果与任务的语义结果，将每一步转换归属于实际执行组件：目标应用、文件操作或外部助手。

## 独立检查输出

| 属性 | 有意义的检查 |
| --- | --- |
| 身份与完整性 | 请求、输出路径、格式与完整解码/解析，排除旧文件和写入未完成的文件 |
| 结构化数值 | 必需字段、类型、ID、关联及无关数值保持 |
| 定量结果 | 单位、范围、维度与定义容差内的数值误差 |
| 可执行行为 | 目标运行时中的所需分支、副作用、无效输入及终态 |
| 持久化 | 支持的重载流程之后，重新获取对象、读取保存值并继续操作 |
| 渲染表示 | 正确来源修订中的预期内容及变换 |

在变化边界前、中、后抽查，核对无关对象及其他相关文档/上下文。导出后同时检查源工程与最终产物。

## 观察契约

[观察模板](../../templates/research/observation.json)记录：

- 产生观察的操作/请求 ID 和精确原生目标；
- 获取时间，以及可获得的源修订号/指纹；
- 来源类型：原生查询、原生渲染/导出、保存文件检查、外部助手或录屏；
- 产物路径、哈希、媒体类型及范围；
- 是否修改/恢复临时状态、是否可能过期。

工具说明和结果应区分原生查询、持久化数据、生成表示及可见应用状态。简洁查询用于选择下一项操作，详细产物用于需要时核对内容。

复用缓存需要源身份及相关参数匹配；源修订无法确认时，标明新鲜度未知或重新获取。通用缓存键不能自行证明原生正确。

## 关联执行与观察

保留命令参数、操作 ID、提交与完成时间戳、结果对象或产物 ID；将后续观察关联到该操作及来源修订。结果迟到时，先与原请求对账，再决定是否需要新的写入。

执行日志记录提交及报告的完成状态，独立观察证明实际结果。操作正确性依赖两者时，应同时保留。
